# 固件的 `/control/` 用静态共享令牌 + 明文 HTTP

ESP32 固件除了只读面（`/status/` `/health` `/diag`）之外，还暴露了十个 `/control/*` 路由，
能重启板子、整份改写配置、轮换令牌、读日志与 coredump。这些路由用**单一静态共享令牌**
鉴权（请求头 `X-StatusCast-Token`），令牌默认值是公开的 `statuscast`，信道是**明文 HTTP**，
绑 `0.0.0.0`，没有速率限制，也没有重放防护。

## 为什么不是 TLS

这是首要问题，所以先说。选明文不是因为它更安全，而是因为当时的取舍：

- 目标是**可信局域网里的一台桌面设备**，不跨公网、没有公网入口、不做多租户；
- 上 TLS 要给设备签发/安装证书，在 `statuscast.local` 这种没有公网域名和 CA 的场景里，
  自签证书会把「浏览器/curl 报证书错误」变成常态，反而训练用户忽略告警；
  私有 CA 则要求每台客户端都装一次根证书；
- 固件已经有 SHA-256（mbedtls）和 `esp_https_server`，技术上不是做不到，是**收益与成本
  在局域网这个信任模型下不成立**。

代价必须写清楚：**令牌和请求体都明文过网，同一网段内可被嗅探，抓到一个请求就能永久重放。**

## 为什么默认令牌是一个公开词

`CONFIG_SC_CONTROL_TOKEN` 默认 `statuscast`，`Kconfig.projbuild` 和 `sdkconfig` 里都写着，
`config_store.c` 还有一份硬编码兜底。看着刺眼，但另一个选择更糟：**每块板子烧一个随机默认值，
就意味着「第一次配网」这一步必须先知道令牌**——而唯一能读到它的通道是串口，也就是你本来就要
用它配网。结果是多一个必填步骤，换不来任何安全增益：任何能接触串口的人本来就能烧固件。

所以真实的安全边界不是「令牌保密」，而是**「谁能到达这个 IP 和端口」**。令牌的作用是把
「顺手扫到 5099 端口就能重启板子」抬到「知道令牌才能重启」，并让审计日志里能区分鉴权失败。

## 已知弱点，以及为什么不现在修

| 弱点 | 现状 | 为什么先留着 |
| --- | --- | --- |
| 不恒定时间比较 | `strcmp` | 在局域网 RTT 抖动下，逐字节比较的时序信号要几千次采样才能利用；加 `timing_safe_cmp` 是一行，但会让「鉴权实现」多一个需要测试的分支 |
| 无速率限制 | 可无限猜 | 与令牌空间（4..63 字符）比，猜测无威胁；真正的威胁是被嗅探，而嗅探不受速率限制约束 |
| 无重放防护 | 静态头可重放 | HMAC + nonce 需要客户端同步时钟，会把 `sc-control.ps1` 从「一行调用」变成「先对时」 |
| 明文 | 可嗅探 | 见上 |

结论：这些都是**已知且已记录的取舍**，不是遗漏。要修，正确顺序是 TLS → 再谈其它三项；
没有 TLS 的单点修修补补没有意义。

## 什么时候必须推翻这个决定

出现下面任一条，这个 ADR 就该被取代：

1. 设备需要从公网或被不可信网络（访客 WiFi、宿舍网、共享办公网）访问；
2. `/control/` 增加任何**不可逆**的能力（清空存储、刷固件、改分区、OTA 到任意 URL）；
3. 有人开始用同一块板子给多个人/多个租户服务；
4. 出现把令牌写进共享脚本、镜像或镜像仓库的用法。

到那时应当走：`esp_https_server` + 私有 CA（或在 `statuscast.local` 上固定自签证书并分发
根证书）→ 换成短期令牌或 HMAC → 补速率限制与审计告警。

## 影响

- 只读面**不加鉴权**，这是 NekoTool 零改动接入的前提，也被 `docs/guide/control-api.md`
  与 `SECURITY.md` 明确写成两种权限等级。
- 固件 README 里「局域网内无鉴权」的旧说法是错的，已修正为「只读面无鉴权、`/control/*` 需令牌」。
- 令牌泄露的处置手段目前只有一处：`POST /control/token` 轮换。**没有**「恢复默认」的路径
  （没有任何代码会删 NVS 里的 `ctl_token`），要回到编译期默认只能擦 NVS。
